# stack-nextjs — conventions

> 작성 시점 기준 일반 규약. 프로젝트의 실제 버전·기존 코드가 우선한다. 불일치는 보고한다.

## 라우트 구조

- `app/` 아래 폴더 = 경로. 라우트 그룹 `(group)` 은 URL 에 영향을 주지 않고 레이아웃 분리에 쓴다.
- 보호 영역과 공개 영역은 레이아웃 그룹으로 분리한다.
- 로딩·에러 경계는 라우트 단위로 둔다(`loading` · `error`).

## 서버/클라이언트 경계

- 기본은 서버 컴포넌트. `"use client"` 는 이벤트 핸들러·상태·브라우저 API 가 필요한 최소 컴포넌트에만.
- 서버 컴포넌트에서 클라이언트 컴포넌트로 넘기는 props 는 직렬화 가능한 값만.
- 서버 전용 모듈(비밀·DB)을 클라이언트 모듈에서 import 하지 않는다.

## 인증 세션 (Supabase)

- SSR 환경에서는 쿠키 기반 세션 클라이언트를 서버/브라우저용으로 구분해 생성한다(`@supabase/ssr` 계열 — 정확한 팩토리 이름은 버전 확인).
- 보호 라우트 판단은 서버에서 한다(미들웨어 또는 서버 컴포넌트). 클라이언트 상태만으로 보호하지 않는다.
- 서비스 롤 키는 `apps/web` 에서 쓰지 않는다. 필요하면 `apps/api` 를 경유한다.

## API 소비

- 기본 URL·키는 환경 변수로 주입한다. 하드코딩 금지.
- 응답은 타입으로 좁히고(검증 라이브러리 또는 생성 타입) 에러 응답 형식을 한 곳에서 처리한다.
- 계약 정본은 설계 산출물과 `apps/api` 의 스키마다. 응답 필드를 추정하지 않는다.

## 파일·명명

- 기존 프로젝트의 파일명·폴더 규칙을 따른다. 새 규칙을 도입하지 않는다.
- 공용 UI 는 기존 컴포넌트 디렉터리에 두고 중복 생성 전 검색한다.
