# stack-nextjs — pitfalls (리뷰 1순위 체크리스트)

| # | 함정 | 증상·위험 | 확인 방법 |
|---|---|---|---|
| 1 | 비밀을 `NEXT_PUBLIC_*` 로 선언 | 키가 브라우저 번들에 노출 | `.env*`, Grep `NEXT_PUBLIC_` |
| 2 | 서비스 롤 키를 웹 앱에서 사용 | RLS 우회·전권 노출 | Grep `service_role`, 키 변수명 |
| 3 | 클라이언트 상태만으로 라우트 보호 | 직접 URL 접근 시 우회 | 보호 라우트의 서버 측 검사 유무 |
| 4 | 서버 컴포넌트 안에서 클라이언트 전용 API 사용 | 빌드·런타임 오류 | `window` · `localStorage` 사용 위치 |
| 5 | 캐싱 기본값을 모르고 데이터 갱신 기대 | 오래된 데이터 표시 | 페칭 옵션·재검증 설정(버전별 기본값 다름 — 확인 필요) |
| 6 | `"use client"` 를 최상위에 남발 | 번들 증가·서버 이점 상실 | 클라이언트 경계가 말단인지 |
| 7 | 에러·로딩·빈 상태 누락 | 빈 화면·무한 로딩 | 라우트별 `loading`/`error` 및 조건 분기 |
| 8 | API 응답을 `any` 로 소비 | 계약 변경 시 조용히 깨짐 | 타입·검증 유무 |
| 9 | 서버 액션 입력 미검증 | 인젝션·잘못된 데이터 | 액션 시작부의 검증·인가 |
| 10 | 환경별 URL 하드코딩 | 배포 환경에서 장애 | Grep `http://localhost` |
