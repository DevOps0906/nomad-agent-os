# stack-supabase — conventions

> 일반 규약. 프로젝트의 실제 설정·기존 마이그레이션이 우선한다. 불일치는 보고한다.

## 마이그레이션

- 위치: `supabase/migrations/`. 파일명은 CLI 가 생성하는 타임스탬프 접두를 따른다.
- 한 마이그레이션 = 하나의 의도(테이블 생성 / 정책 추가 / 인덱스 추가). 섞지 않는다.
- 이미 적용된 파일은 수정하지 않는다. 고칠 때는 새 마이그레이션으로 변경한다.
- 파괴적 변경은 데이터 이전 단계와 되돌리기 방법을 주석으로 남긴다.

## RLS

- 테이블 생성과 같은 마이그레이션에서 RLS 를 켠다.
- 소유권 컬럼(예: 사용자 ID)을 두고 `auth.uid()` 와 비교하는 정책을 기본으로 한다.
- 정책은 동작별(select/insert/update/delete)로 분리하고, update 는 using 과 with check 를 모두 고려한다.
- 정책에서 조회하는 컬럼에는 인덱스를 둔다(정책은 모든 쿼리에 덧붙여진다).
- 서비스 롤은 RLS 를 우회한다 — 서버 전용이며 사용 이유를 남긴다.

## Auth·Storage

- 역할·권한 정보는 앱 메타데이터 또는 별도 테이블에 두고, 사용자가 수정 가능한 메타데이터를 인가 근거로 쓰지 않는다.
- Storage 버킷 접근도 정책으로 제어한다. 공개 버킷은 의도를 문서화한다.

## 타입·시드

- DB 변경 후 앱 타입을 재생성한다(명령은 `build-and-run.md`). 생성 파일은 직접 수정하지 않는다.
- 시드 데이터에 실제 개인정보·키를 넣지 않는다.
