# bm-model — 사업모델 7단계 (계산은 코드, 판단은 사람·AI)

## 원칙
1. **계산은 반드시 `~/.claude/nomad/bin/bm-calc`**. LTV·BEP·점수 합계를 모델이 암산·추정하지 않는다.
2. 모든 수치는 가정치. 출처·측정 시점·증거 등급을 적고 검증하며 교체한다.
3. "단계 완료"는 입력 형식 완결일 뿐 시장 검증 완료가 아니다.
4. 6단계 통과 기준은 실험 전에 숫자로 적는다(사후 변경 금지).

## 7단계 절차
| 단계 | 입력 | 완료 조건 | 담당 |
|---|---|---|---|
| 1 고객·문제 | 타깃, 문제, 현재 대안, 검증 질문 | 고객군 1개+ | planner |
| 2 가치 제안 | 정량 가치 문장(비용·기간 절감), 차별성 | 가치 제안 1개 | planner |
| 3 수익모델·가격 | 플랜별 가격·과금 단위·가격 근거(경쟁 단가) | 유료 플랜 1개+ | planner |
| 4 단위경제 | 변동비 항목, 이탈률, 고정비, (실)CAC, 시나리오 | `bm-calc` 실행 완료 | **bm-calc** |
| 5 파트·공통비 | 파트별 역할·수익모델, 배분 기준(원인 기준: 서버·API=사용량, 인건비=투입시간) | 배분 합계 = 원 총비용 | planner |
| 6 린 검증 | 가설, 방법, 지표, 표본, 통과·실패 기준, 기간, 증거 | 실험 1개+ | planner |
| 7 사업성 점수 | 5축×20점(축마다 세부 4지표×0~5), 증거 연결 | 합계·판정 산출 | bm-calc + 증거 연결 |

## 4단계: bm-calc
- `bm-calc --init bm-input.json`으로 예시를 만들어 값을 교체하고 `bm-calc bm-input.json`(표) 또는 `--json`.
- 산출: 공헌이익·률, LTV(=월 공헌이익÷월 이탈률), CAC 상한(=LTV÷목표배수, 기본 3), 실CAC가 있으면 LTV/CAC·회수기간, BEP=ceil(고정비÷공헌이익), 시나리오(보수·기준·낙관 override) 표.
- CAC 상한(허용)과 실CAC(가정·측정)는 **별개 필드**. 섞어 쓰지 않는다.
- 경고(이탈 0·공헌이익≤0)는 결과 문서에 그대로 옮긴다.

## 7단계: 점수와 증거
- 축: 시장성·수익성·검증도·실행가능성·확장성(각 20). 판정: 80+ MVP 개발·신청 / 60~79 부족한 축 추가 검증 / 40~59 노코드 MVP 축소 / 40 미만 보류.
- **blocking 조건**(법적 문제, 실결제 검증 0건 등)이 하나라도 있으면 점수와 무관하게 보류. 입력의 `score.blocking`에 적는다.
- 증거 등급: A 실결제·계약·사용 로그 / B 고객 행동·사전예약 / C 인터뷰·설문 / D 경쟁사·시장조사 / E AI 추정·창업자 가정(미검증).
- 점수 축마다 증거 등급을 연결한다. E 등급만 있는 축은 높은 점수를 줄 수 없다(제안: 검증도 축은 A·B 없이 10점 초과 금지). A도 통계적 타당성을 보장하지 않는다.
