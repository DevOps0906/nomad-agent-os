# 위협 메모 — 기능당 10줄

기획(PRD·03_SCREENS_UX·04_API) 단계에서 기능마다 아래 표를 채운다. 길게 쓰지 않는다. 목적은 **"어디가 노출되고, 뚫리면 어디까지 가나"**를 미리 정하는 것.

| 항목 | 질문 | 예 |
|---|---|---|
| 노출 면 | 인터넷에서 누가 부를 수 있나 | 공개 API `POST /api/upload`, 웹훅, 관리자 화면, 공개 링크 |
| 인증·인가 | 누가 무엇을 할 수 있나, 조직 경계는 | 세션 필수 · 같은 org만 · owner만 삭제 |
| 다루는 데이터 | 개인정보·결제·토큰·원본 파일 | 이메일, OAuth 토큰(vault), 결제 키 없음 |
| 필요한 키·권한 | 이 기능이 쓰는 키와 그 범위 | service_role(서버만), 외부 API 키(읽기 전용) |
| 입력 | 신뢰할 수 없는 입력과 검증 | 파일(크기·형식·확장자), URL(허용 목록), 텍스트(zod) |
| 체인 | 이 기능의 약점이 다른 것과 이어지면 | 업로드 경로 노출 + 미검증 파일명 → 경로 조작 |
| 피해 범위 | 뚫리면 어디까지 닿나 | 해당 org 파일만 / 전체 버킷 / 다른 서비스 키 |
| 남용 | 정상 기능을 과하게 쓰면 | 레이트 리밋, 크레딧 선차감, 비용 폭주 |
| 로그 | 무엇을 남기고 무엇을 남기지 않나 | 감사 로그 O, 토큰·본문 X |
| 결정 | 위 내용으로 정한 것 | "업로드는 서명 URL 10분, 서버에서 재검증" |

reviewer(security)는 구현이 이 표의 결정을 지켰는지 본다. 표가 없는 노출 면 추가는 🔴.
