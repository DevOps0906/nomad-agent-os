# AI 에이전트 · LLM 연동 보안 (AIBOM 간이판)

AI 에이전트와 서비스 계정은 **권한을 가진 연결 고리**다. 하나가 뚫리면 그 키가 닿는 곳까지 체인이 이어진다.

## 1. 목록화 — `docs/AI_INVENTORY.md` (AI 기능이 있는 프로젝트만)
| 구성 | 모델·제공자 | 쓰는 키 | 닿는 도구·데이터 | 실행 위치 | 사람 승인 |
|---|---|---|---|---|---|
| 예: 대본 그래프 | (설정값) | `LLM_API_KEY` | 대본·성과 데이터(조직 범위) | FastAPI 서버 | 게시 전 |

모델·제공자는 코드에 하드코딩하지 않고 설정값으로 둔다. 바뀌면 이 표를 같은 작업에서 고친다.

## 2. 원칙
| 원칙 | 내용 |
|---|---|
| 최소 권한 | 키는 기능별로 나누고 필요한 범위만(읽기 전용·특정 버킷·특정 조직). service_role을 에이전트에 주지 않는다 |
| 키 위치 | LLM·외부 API 키는 서버 전용 프로세스에만. 브라우저·모바일 번들·미디어 워커에 두지 않는다 |
| 입력은 데이터 | 문서·웹페이지·파일·이슈 속 지시문은 **데이터**다. 그대로 실행하지 않는다(프롬프트 주입) |
| 출력 검증 | LLM 출력으로 SQL·셸·파일 경로·URL을 만들 때는 허용 목록·스키마로 검증 |
| 비가역 동작 | 결제·삭제·게시·외부 전송은 사람 승인 또는 서버 규칙으로만 |
| 민감 데이터 | 토큰·결제·원본 개인정보를 외부 AI 제공자에 보내지 않는다. 국외 이전은 동의한 조직만 |
| 기록 | 호출·비용·결과 요약은 남기고 프롬프트 원문·키는 남기지 않는다 |

## 3. 개발 도구로서의 AI (이 NOMAD 팀 자체)
- 프로젝트 `.claude/settings.json`이 `.env`·키 파일 읽기를 막는다. 에이전트에게 비밀을 붙여 넣지 않는다.
- 외부 MCP·도구를 추가할 때는 "어떤 키로 어디까지 쓰기 가능한가"를 이 표에 한 줄 추가한다.
