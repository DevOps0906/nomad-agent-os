# 규제 · 표준 메모 (L3 판단용)

> **기준일 2026-10. 일정·세부 요건은 바뀌므로 납품·판매 협의 시점에 원문으로 재확인한다. 법률 자문이 아니다.**

## 1. 의무가 생기는 경우
| 상황 | 요약 | 확인할 곳 |
|---|---|---|
| 개인·자체 운영 SaaS | 법적 의무 없음. L0~L2 권장 | — |
| 국내 공공기관 납품 | 국정원이 2027년부터 공공 정보화사업·보안검증에 SBOM 제출을 **단계적** 적용 예정(일괄 의무 아님) | 국정원 · KISA 공지, 발주 RFP |
| EU에 디지털 제품 판매(설치형·앱·SDK·임베디드) | EU CRA: 악용 중 취약점 24시간 내 보고 의무가 2026-09-11부터, 전면 적용 2027-12-11. 기계 판독 SBOM을 기술문서에 보관(공개 의무 아님, 요청 시 제출) | EU CRA 원문, BSI TR-03183-2 |
| 순수 클라우드 SaaS의 CRA 적용 | 대체로 범위 밖으로 알려져 있으나 앱·SDK로 배포하는 부분은 해당될 수 있음 → **전문가 확인** | — |
| 미국 연방·국방 납품 | 사실상 SBOM 요구 | 계약 조건 |
| 대기업·금융 B2B 보안 심사 | 계약 조건으로 SBOM·취약점 대응 절차 요구 증가 | 고객 보안 질의서 |

## 2. 표준
| 표준 | 무엇 | 쓰임 |
|---|---|---|
| CycloneDX | SBOM 형식(보안 중심, VEX 포함 가능) | 기본 형식 |
| SPDX (ISO/IEC 5962) | SBOM 형식(라이선스 중심) | 고객·규제 요구 시 |
| OpenChain ISO/IEC 5230 | 오픈소스 **라이선스 컴플라이언스 프로그램** 표준 | 정책·절차·증빙 갖추기 (자가 인증) |
| OpenChain ISO/IEC 18974 | 오픈소스 **보안 보증 프로그램** 표준 | 취약점 대응 절차 갖추기 (자가 인증) |
| CISA KEV · FIRST EPSS | 악용 확인 목록 · 악용 가능성 예측 | 우선순위([vuln-priority.md](vuln-priority.md)) |

OpenChain은 SBOM 형식이 아니라 **관리 체계**의 표준이다. SBOM은 그 체계를 충족하는 수단 중 하나다.
무료 자가 체크리스트와 정책 템플릿(CC0)은 https://openchainproject.org 의 Projects · Learning에서 받는다.

## 3. L3로 올라갈 때 할 일 (별도 팩 `nomad-secure-pack`에서 다룰 예정)
5230·18974 자가 체크리스트로 갭 분석 → 오픈소스 정책 문서 → VEX 운영 → SPDX 산출 → CRA 필드 보강 → 고객 제출 양식.
