# stack-fastapi — conventions

> 일반 규약. 프로젝트의 실제 버전·기존 코드가 우선한다. 불일치는 보고한다.

## 라우터·모델

- 기능별 라우터 모듈 + 요청/응답 모델 분리(입력용·출력용·DB용 모델을 한 클래스로 합치지 않는다).
- 응답은 `response_model` 로 노출 필드를 제한한다(비밀번호·내부 ID 누출 방지).
- 상태 코드는 의미에 맞게(생성 201, 삭제 204, 검증 실패 422, 인가 실패 403, 미인증 401).
- 경로·필드 명명은 기존 API 와 일관되게. 새 규칙을 도입하지 않는다.

## 인증

- Supabase 발급 JWT 를 서버에서 검증하는 의존성을 두고, 보호 라우터에 일괄 적용한다(검증 방법·키 형태는 프로젝트 설정 확인 필요).
- 인증(누구인가)과 인가(무엇을 할 수 있나)를 분리한다. 소유권 확인은 핸들러에서 명시적으로 한다.
- 서비스 롤 키 사용은 서버 전용이며, 사용 이유를 코드 주석으로 남긴다. 가능하면 사용자 토큰 기반 접근으로 RLS 를 활용한다.

## 설정

- 환경 변수는 설정 모델(Pydantic Settings 계열)로 한 곳에서 읽는다. 값은 저장소에 두지 않고 `.env.example` 에 키만 둔다.
- CORS 허용 오리진은 명시 목록으로 두고 `*` 와 자격 증명 허용을 함께 쓰지 않는다.

## 비동기

- I/O 라이브러리가 동기식이면 `def` 핸들러(스레드풀 실행)로 두거나 별도 스레드풀로 격리한다.
- 요청 하나에서 반복 쿼리·원격 호출을 루프로 돌리지 않는다(일괄 조회).

## 로깅·에러

- 요청 본문·토큰·키를 로그에 남기지 않는다.
- 예외 핸들러에서 일관된 에러 본문(코드·메시지)을 반환한다.
