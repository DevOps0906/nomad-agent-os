1. NOMAD란

NOMAD Agent OS는 Claude Code를 AI 개발팀처럼 쓰게 해 주는 설정 모음입니다. 사용자가 여는 주 세션이 팀장(Opus 5.5)이 되어 일을 나누고, 팀원 12명(Claude 10명 + Codex 중계 2명)이 기획 · 디자인 · 구현 · 테스트 · 독립 검증을 맡습니다. 기획 · 디자인은 Sonnet과 Codex가 초안을 나눠 쓰고, 구현은 Sonnet, 검증은 Codex가 따로 합니다. 같은 파일을 반복해서 읽지 않게 막고, 그림 · 문서 뼈대는 모델 대신 스크립트가 만들어 토큰을 아낍니다. ChatGPT(Codex) · Gemini CLI도 같은 규칙(AGENTS.md)을 읽습니다. 도메인 기획 청사진(CRM · LMS 등)은 본체에 넣지 않고 모듈로 필요할 때만 가져옵니다.

4. 프로젝트 적용

적용은 프로젝트마다 한 번입니다. nomad-os는 전역 설치 때 만들어지며 어느 폴더에서나 실행합니다.

상황명령
새 프로젝트nomad-os init <프로젝트 경로> --name "<제품명>" → cd <프로젝트> → git init -b main → claude
기존 저장소먼저 git clone … → nomad-os init <저장소 경로> → cd <저장소> → claude (순서가 반대면 clone이 실패)

만들어지는 파일과 이유

파일이유
AGENTS.md가장 중요. 스택 · 명령 · 규칙의 단일 정본. 모든 AI 도구가 읽음
CLAUDE.mdClaude Code용. AGENTS.md를 불러옴
.claude/Claude Code 설정(모델 지정 · .env 등 읽기 차단) · 영역 규칙
.codex/ChatGPT Codex 설정 (샌드박스 · 승인)
.gemini/ · .geminiignoreGemini CLI가 AGENTS.md를 읽게 하고 .env 등을 제외
tasks/작업 표(README.md)와 재진입 스냅샷(NOW.md) — /next가 따라 움직임

안심해도 되는 점

항목내용
덮어쓰기이미 있는 파일은 덮어쓰지 않고 필요한 줄만 추가
gitgit 명령을 실행하지 않음 (git init은 새 폴더에서 직접)
경로nomad-agent-os 저장소 안의 경로는 거부. 상위 폴더가 없으면 오타로 보고 멈춤

기존 저장소라면 — AGENTS.md를 실제 코드에 맞추기

템플릿의 스택 · 명령(pnpm dev 등)은 예시입니다. /check · /next가 이 명령을 그대로 실행하므로 Claude에게 이렇게 요청합니다.

이 저장소를 분석해서 AGENTS.md의 스택 · 명령 표와 7장 영역 규칙 경로를 실제에 맞게 채워줘

5. 팀원 12명

팀장이 알아서 나눠 맡기므로 직접 부를 일은 거의 없습니다. /agents로 확인합니다.

Codex 모델은 ~/.codex/config.toml의 기본값을 따릅니다. Codex 팀원이 한도 · 미설치로 실패하면 상태: Codex 불가를 보고하고, 팀장이 Claude 팀원으로 대체합니다.

팀장이 직접 하는 일: 한 줄 수정, 위임 비용이 더 큰 일.

위임 규격

팀원에게 주는 지시는 5줄, 600자 이내입니다. 문서 내용을 붙여 넣지 않고 경로#장만 넘깁니다. 팀원 보고는 20줄 이내입니다.

6. 명령어

슬래시 명령 (Claude Code에서 입력)

명령언제무엇을
/agent-check · /agent-check fix설치 직후 · 이상할 때전역 설치 · 프로젝트 적용 · 템플릿 미작성 · 규칙 경로 · 팀원 이름 충돌 · 모듈 · 사양 최신 · 보안 · 준비물 · 토큰 점검, fix는 안전한 것 자동 구성
/plan 제품명처음부터 기획할 때린 검증 → PRD → 명세 → 작업 분해 (docs/에 문서 뼈대 8개, tasks/에 작업 목록)
/design기획 뒤 화면 구현 전디자인 토큰 → 반응형 폰트 → 미리보기 HTML. 확정 전 화면 구현 시작 안 함
/diagram 무엇그림이 필요할 때구조도 · 흐름도 · 시퀀스 · ERD (예: /diagram 결제 흐름, /diagram erd)
/next개발 반복 · 쉬었다 이어갈 때다음 작업 하나를 계획 → 위임 → 검증 → 커밋까지. 끝나면 /clear 후 다시 /next
/check수시로린트 · 타입 · 테스트를 돌리고 실패만 요약
/secure · /secure setup [--ci]보안 점검 · GitHub 저장소가 생긴 뒤SBOM · 취약점 · 라이선스 점검 / Dependabot · SECURITY.md · CI SBOM 생성

7. 기본 작업 흐름

새 프로젝트 — SDLC 9단계

먼저 nomad-os init <경로> --name "<제품명>" → cd → git init -b main → claude로 적용합니다. 이후 아래 9단계를 따르며, 02~07은 기능 하나씩 반복합니다. 단계가 끝날 때마다 tasks/NOW.md가 갱신됩니다.

8. 모듈 개요

모듈은 코드가 아니라 기획 청사진입니다(화면 · 상태 · 흐름 · API · 데이터 표 + 도메인 분석). 가져와서 쓰지 않을 행을 지우고, plan2spec으로 시안 · 검사를 만든 뒤, 팀이 내 스택으로 구현합니다. 코드를 그대로 가져오지 않는 이유는 오픈소스 CRM · ERP · LMS가 AGPL · GPL 계열이거나 거대한 단일 앱이라, 구조만 벤치마킹하는 편이 안전하기 때문입니다.

아래 표의 버전 · 규모 · requires · integrates는 nomad-blueprints-module의 각 module.json 기준입니다. 규모는 화면 · 흐름 · API · 테이블 수입니다. docker 모듈만 nomad-docker-module 레포(기본 브랜치 master)에 있고, 나머지는 모두 nomad-blueprints-module에 있습니다.

plan2spec --strict

booking은 본체 modules.json에 등록된 뒤에 module add가 동작합니다(8장 참고).

고객지원

nomad-os module add helpdesk .      # files-storage가 requires로 함께 설치됨
nomad-os module add crm .
nomad-os module add notify .
plan2spec --strict

helpdesk도 등록 후에 동작합니다. 조합이 정해지면 /plan에서 "docs/blueprints의 모듈 기준으로 PRD를 채워줘"처럼 요청해 기획에 반영합니다.

11. docker 모듈

blueprints가 정한 자체 호스팅 서비스를 로컬 · 단일 서버에서 실행하는 템플릿입니다(쿠버네티스 등 운영 오케스트레이션은 범위 밖). 이 compose는 외부 API를 호출하지 않습니다(STT · OCR · 임베딩 모두 자체 호스팅).

설치

nomad-os module add docker <프로젝트> --allow-scripts

→ 프로젝트 infra/docker/. 설치 전 compose.yml · Dockerfile을 직접 검토합니다. 셸 스크립트(.sh 등)는 플래그가 있어도 거부되고, Dockerfile · .dockerignore · .env.example · .conf · .toml만 추가 허용됩니다.

12. 공통 계약 (contracts)

여러 모듈에 복사돼 있던 공통 규칙의 정본 1곳입니다. 각 모듈은 규칙을 복사하지 않고 ../contracts/<문서>로 링크합니다. 규칙을 한 곳에서 고치면 모든 모듈이 같이 따라가고, 모듈끼리 이벤트 · 권한 · 표기 방식이 어긋나지 않습니다. 그래서 대부분 모듈의 requires이며 함께 가져와야 문서 링크가 열립니다.

문서한 줄왜 필요한가
EVENTS이벤트 봉투 12필드 · outbox/inbox · HMAC · 순서 · 모르는 type 처리모듈 간 연결(결제 완료 → 수강 등록)이 같은 형식이어야 안 깨짐
JOBSAI 작업 테이블 · 단계 · 상태 전이 · 재시도=새 작업 · 환불 멱등 키AI 모듈(stt · rag · ocr)이 같은 작업 모델을 쓰고 중복 실행 · 중복 환불을 막음
ACCESShas_permission · 플랫폼 운영자 · 서비스 키 · 서버 간 인증 · owner_module권한 판단과 서비스 키 사용을 한 규칙으로 통일
CONVENTIONS금액 · VAT · 개인정보 마스킹 · "확인 필요" 표기 · 이벤트 이름 · ID 접두사 표표기가 모듈마다 달라지는 것을 막음
  • 모듈 고유 값(type 목록 · kind · step · payload)은 해당 모듈에 두고, 공통 규칙만 contracts에서 가져옵니다.
  • 계약이 바뀌면 minor 버전이 오르고, 참조하는 모듈이 영향을 받는지 확인합니다.

"확인 필요" 표기의 의미
